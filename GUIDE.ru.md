mailtmp — гайд по утилите
========================

Что это
-------
Временная почта для регистраций на сайтах. Работает поверх публичного API
mail.tm. Свой домен не нужен, VPS не нужен, почтовый сервер не нужен —
адрес реально принимает письма.

Файлы:
  сама утилита    ~/.local/bin/mailtmp
  состояние       ~/.local/state/mailtmp/state.json  (права 600)

Зависимостей нет вообще — только стандартная библиотека python3.
Работает одинаково из терминала и из лаунчера, если PATH содержит
~/.local/bin (в ~/.bashrc он прописан).


Команды
-------

mailtmp new
    Создать новый адрес и запомнить его. Печатает адрес в stdout,
    путь к файлу состояния — в stderr.
    Старый адрес при этом просто забывается (не удаляется на сервере).

mailtmp addr
    Показать текущий адрес. Ничего не создаёт.

mailtmp domains
    Показать домены, доступные сейчас. Обычно один.

mailtmp inbox
    Список писем. Формат: первые 8 символов id · дата · отправитель · тема.
    Пустой вывод — «пусто».

mailtmp read N
    Показать письмо. N — это первые 8 символов id из списка inbox,
    можно ввести хоть первые 4, сверяется по началу.

mailtmp wait [секунды]
    Ждать НОВОЕ письмо и вывести на stdout код подтверждения или ссылку.
    По умолчанию ждёт 90 секунд.
    Что выведет — то и нужно вставить на сайт.
    Новое = то, что пришло после запуска команды. Уже лежавшие в inbox
    игнорируются.
    Если письмо пришло, а кода в нём нет — напечатает об этом в stderr.

mailtmp reset
    Забыть текущий адрес и пароль. Сам ящик на сервере mail.tm
    при этом остаётся жив до 7 дней.

mailtmp help
    Этот же текст.


Типовой сценарий — регистрация на сайте
---------------------------------------

В одном терминале:

    mailtmp new
    → yiivhwaqlg@maxxspace.com

Скопировать адрес, вставить на сайте, нажать «получить код».
Во втором терминале:

    mailtmp wait 120

Как только письмо дойдёт — в stdout выпадет либо шестизначный код,
либо ссылка активации. Вставить на сайт. Готово.

Если код не подошёл и нужна новая почта:

    mailtmp new
    mailtmp wait 120

Старый адрес можно оставить — он ничего не занимает.


Коды возврата
------------

0   успех
1   ошибка (сеть, HTTP, нет текущего адреса)
2   таймаут ожидания письма, либо вызвана без аргументов


Известная шероховатость
----------------------

Цикл опроса спит по 4 секунды, поэтому wait выходит за заданный срок
максимум на 4 секунды. Измерено: `mailtmp wait 6` отработал за 9 секунд
и вернул код 2. Если точность важна (например, ты пишешь обвязку в скрипте),
учитывай это или оборачивай в свой таймаут.


Что она достаёт из письма
-------------------------

Порядок такой: сначала ищется код, только потом ссылка.

Код ищется по двум шаблонам:
  1. помеченный — «code», «код», «pin», «пин», «otp», «verification»,
     «verify», «подтверж» и ближайшие 30 символов после них, затем цифры
  2. любой — первая последовательность из 4–8 цифр

Ссылка ищется по сырому HTML и по тексту письма.

Проверено на 9 кейсах, все проходят: код в теме, код в теле, код в HTML,
OTP, ссылка в HTML, ссылка в тексте, приоритет кода над ссылкой,
посторонние числа в обычном письме, письмо без кода.

Известное ограничение: если в обычном письме есть посторонние числа
(«Order 99201 shipped»), утилита выдаст их как код. Это осознанный
компромисс — ради простоты без зависимостей.


Ограничения сервиса
-------------------

Домен бесплатный и общий. Сайты всё чаще проверяют одноразовые домены по
спискам и могут отказать в регистрации. Для мелких сайтов, форумов и
игровых регистраций обычно проходит.

Письма хранятся на стороне mail.tm 7 дней.
Лимит API — 8 запросов в секунду.
Отправлять письма с этих адресов нельзя, только принимать. Для логина
и подтверждений этого достаточно.

Домен меняется без предупреждения — список всегда актуальный в
`mailtmp domains`.


Безопасность
------------

Пароль генерируется системным CSPRNG и лежит только в
~/.local/state/mailtmp/state.json с правами 600.

Файл НЕЛЬЗЯ класть в любой каталог, который куда-то синхронизируется
(облачный диск, rsync на свой сервер, шара). Он содержит пароль от ящика
и токен к API.

Это одноразовые адреса для регистраций. Не привязывать к ним ничего
ценного — ни платежей, ни восстановления доступа к рабочим аккаунтам.


Если что-то пошло не так
-------------------------

«нет текущего адреса»
    → mailtmp new

«сеть недоступна»
    → нет интернета, либо api.mail.tm недоступен.
      Проверить: curl -s https://api.mail.tm/domains

«HTTP 429»
    → превышен лимит 8 запросов/сек. Подождать пару секунд.

HTTP 401 при wait
    → адрес удалён на стороне сервиса (прошло 7 дней). Сделать mailtmp new.

Письмо пришло, но код не извлёкся
    → посмотреть глазами: mailtmp inbox, затем mailtmp read N

Не открывается вообще
    → ls -l ~/.local/bin/mailtmp (должно быть -rwxr-xr-x)
       chmod +x ~/.local/bin/mailtmp
       и убедиться, что ~/.local/bin есть в PATH:
       echo $PATH | tr ':' '\n' | grep local/bin
